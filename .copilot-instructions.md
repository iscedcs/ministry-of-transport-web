# GitHub Copilot Instructions — Ministry of Transport Platform

## Project Overview

Building an Integrated Transport Services Automation Platform for Anambra State Ministry of Transport as a Public-Private Partnership (PPP). This is a mission-critical system that consolidates park approval, mass transit registration, vehicle inspection, accident reporting, and driving school management into a unified web platform.

**Document Reference:** PRD v2.0 (April 2026) in `/docs/PRODUCT REQUIREMENTS DOCUMENT (1).md`

## Design System & Brand Identity

### Color Palette (OKLCH Format)

The platform uses a professional, government-grade color system anchored to the Ministry logo colors:

- **Primary Accent:** #f0bb0d (Gold) → `oklch(76% 0.24 80)` — CTAs, highlights, approvals
- **Dark Foundation:** #452829 (Dark Brown) → `oklch(20% 0.06 15)` — Page background

### Design Tokens

```css
:root {
  /* Brand Colors */
  --brand-gold: oklch(76% 0.24 80); /* Primary CTA */
  --brand-dark: oklch(20% 0.06 15); /* Page BG */

  /* Semantic Colors */
  --success: oklch(65% 0.18 155); /* Approvals, verified */
  --warning: oklch(75% 0.19 65); /* Attention needed */
  --error: oklch(60% 0.22 25); /* Rejections, critical */
  --info: oklch(62% 0.21 265); /* Notifications */

  /* Surfaces & Text */
  --bg-primary: oklch(20% 0.06 15); /* Main background */
  --bg-secondary: oklch(28% 0.05 15); /* Cards, panels */
  --bg-tertiary: oklch(35% 0.05 15); /* Elevated surfaces */
  --text-primary: oklch(95% 0.01 95); /* Main text */
  --text-secondary: oklch(70% 0.02 265); /* Secondary text */
  --text-muted: oklch(50% 0.01 265); /* Disabled, helpers */
  --border: oklch(30% 0.03 15); /* Dividers */

  /* Typography */
  --font-sans: "Inter", system-ui, sans-serif;
  --font-display: "Clash Display", "Cabinet Grotesk", sans-serif;
  --font-mono: "Geist Mono", monospace;

  /* Radius (Government UI should be approachable but professional) */
  --r-sm: 0.375rem;
  --r: 0.75rem;
  --r-lg: 1.25rem;

  /* Motion (Accessible, professional pacing) */
  --ease-out: cubic-bezier(0.22, 1, 0.36, 1);
  --dur: 250ms;
  --dur-slow: 400ms;
}
```

### Design Philosophy

- **Not random:** Every color, spacing, and component follows the token system
- **Solid system:** Reusable component library with clear patterns
- **Professional:** Government entities deserve polished, accessible interfaces
- **Accessible:** WCAG AA minimum; high contrast ratios for all text

## Technology Stack

### Frontend

- **Framework:** Next.js 15+ with App Router
- **UI Components:** React 19 + TypeScript
- **Styling:** Tailwind CSS v4 with custom tokens plugin
- **Animations:** Native CSS (scroll-driven-animations, view-transitions) — no JS animation libraries
- **Forms:** React Hook Form + Zod validation
- **Tables:** TanStack Table v8 for data-heavy modules

### Backend

- **Runtime:** Node.js (Next.js API routes + standalone backend if needed)
- **Database:** PostgreSQL (to be hosted on Neon for dev/staging)
- **Payment:** Paystack REST API (see `PAYSTACK_INTEGRATION.md`)
- **Authentication:** Role-based (Ministry staff) + ASIN-based (external applicants)
- **File Storage:** Cloud storage for document uploads (GCS or local minio)

### DevOps & Infrastructure

- **Deployment:** Vercel (Next.js frontend) + Neon (Database)
- **Environment:** Staging → Production
- **Monitoring:** Error tracking (Sentry), analytics (PostHog)
- **Backup:** Daily automated backups (Neon + external S3)

## Development Workflow

### Before Writing Code

1. **Check the Epics file** (`docs/EPICS.md`) — what are we building?
2. **Read Roles & Duties** (`docs/ROLES_AND_DUTIES.md`) — what role sees this?
3. **Use Design System** — every color and spacing comes from tokens
4. **Reference PayStack Skill** — see `/memories/skills/paystack-*.md` for payment patterns

### Component Development

- Start with the **Design System** document
- Build in the `/components/ui/` folder using tokens only
- Test accessibility (keyboard nav, screen reader, contrast)
- Document prop interface in JSDoc

### Modules (Epics)

- Each module (Parks, Mass Transit, etc.) is an epic with multiple stories
- Track progress in `docs/PROGRESS.md`
- Reference PRD functional requirements (FR-XXX)

### API Development

- All Ministry APIs secured with role-based auth
- Paystack integration in `/lib/api-client/paystack.ts`
- Request/response validation with Zod

## Guardrails & Standards

### Code Quality

- TypeScript strict mode, no `any` types
- All user inputs validated with Zod
- All database queries parameterized (Prisma)
- Environment variables validated at runtime

### Security

- HTTPS everywhere (TLS 1.3)
- CSRF protection on all forms
- Rate limiting on API endpoints
- Secrets never committed (use `.env.local`, `.gitignore`)

### Accessibility

- WCAG 2.1 AA minimum
- All interactive elements keyboard accessible
- Color is never the only means of conveying information
- Form labels + error messages always present

### Performance

- SSR where possible; ISR for static content
- Image optimization (Next.js Image component)
- Code splitting by route
- Target: Lighthouse 90+

## Getting Started

1. **Clone & Install**

   ```bash
   git clone <repo>
   cd ministry-of-transport
   pnpm install
   ```

2. **Setup Environment**

   ```bash
   cp .env.example .env.local
   # Fill in: PAYSTACK_SECRET_KEY, DATABASE_URL, etc.
   ```

3. **Review Documentation**
   - Start with `docs/IMPLEMENTATION_PLAN.md`
   - Then read `docs/DESIGN_SYSTEM.md`

4. **Run Development Server**

   ```bash
   pnpm dev
   # http://localhost:3000
   ```

5. **Track Progress**
   - Check `docs/PROGRESS.md` for current sprint
   - Update as you complete stories in `docs/EPICS.md`
